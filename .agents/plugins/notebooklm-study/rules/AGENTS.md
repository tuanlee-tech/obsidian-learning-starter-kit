# NotebookLM Study Plugin Rules

1. **Connection, Init, Health-Check & Re-Benchmark Routing:**
   - When the user sends `/notebooklm-connect` or specifically asks to connect, install, repair Android/PC NotebookLM MCP, refresh cookies, or switch `proot` ↔ `remote` mode (`kết nối notebooklm`, `cài mcp`, `cập nhật cookie`, `đăng nhập notebooklm`, `chuyển remote mcp`, `fix mcp android`), **activate the `notebooklm-connect` skill** first.
   - When the user sends `/init`, asks for vault health check (`kiểm tra kết nối`, `health check`), opens a clean-slate vault (`CHƯA KHỞI TẠO` in `CLAUDE.md`), or explicitly asks to re-benchmark an existing roadmap (`cập nhật roadmap theo JD mới`, `re-benchmark roadmap`), **activate the `study-init` skill** to verify `uv`/`uvx` (or Android proot/remote shim), auth cookies, live MCP tools (`server_info` + `notebook_list`), and `docs/notebooklm-system-prompt.md` char budget before running adaptive discovery, 4-mode Ground-Truth Anchor (JD/Syllabus/Spec), Blueprint Approval Gate, or non-destructive Re-Benchmark.
2. **Active Notebook Routing:** When the user is in an active NotebookLM study session (see `.agents/plugins/notebooklm-study/.state/active-notebook.json` or the current conversation) and sends `/outline`, `/teach`, `teach`, `tiếp`, `/flash-1`, `/flash-2`, `/export`, `kết bài`, `chốt bài`, or an answer/follow-up question to NotebookLM's quiz, **activate the `study-session-and-sync` skill** and forward the turn to NotebookLM via MCP (`notebook_query_start` + `notebook_query_status`). Never improvise or replace NotebookLM's lesson text with your own answer.
3. **Exact Pass-Through During `/teach`:** Present NotebookLM's `result.answer` verbatim (preserving Markdown, diagrams, and quiz question) so the learning experience matches NotebookLM Web/Mobile 100%.
4. **Prompt Budget:** Always merge `docs/notebooklm-system-prompt.md` (`<= 8,350` chars from `# SYSTEM INSTRUCTION`) + the day's `Lesson Scope` block (`<= 1,400` chars) into `chat_configure` (`<= 10,000` chars total).
5. **Multi-Source Non-Blocking Ingestion:** Support all 4 NotebookLM `source_add` types (`url`, `file`, `drive`, `text`) using `study_helper.py parse-day`. Always call `source_add(..., wait=False)` and poll `notebook_get` until all sources appear indexed instead of blocking with `wait=True`.
6. **Cross-Platform Onboarding (PC & Android):** If NotebookLM MCP tools are unavailable or return an auth error on any OS (Windows, macOS, Linux, or Antigravity for Android), run `python .agents/plugins/notebooklm-study/scripts/study_helper.py check-env --live` (or `nlm_connect.py detect` & `health`) and activate **`notebooklm-connect`** to handle OS-appropriate remediation (`uv` + `nlm login` on PC; `proot-distro` Debian + smart `uvx` shim or `remote` HTTP bridge + safe cookie import on Android AGY).
7. **Phase-Aware Model Tier Suggestion (Non-Blocking):** Give a brief 1-line model suggestion (with exact model name & version) ONLY at major phase transitions (never repeat on every `/teach` turn):
   - **Fast / Light tier** (`Gemini 3.8 Flash (Low / Medium)` or `Claude Sonnet 5.5 (Low)`) for `study-init` Phase 1 (Health Check), `study-day-init`, and multi-turn `/teach` MCP pass-through (NotebookLM does the teaching).
   - **Balanced / High tier** (`Claude Sonnet 5.5 (Medium / High)`, `Gemini 4 Argon (Medium / High)`, or `Gemini 4 Neon (Medium / High)`) for `kết bài` / `đồng bộ` (`/pre-ingest` → Auto-Enrich → 5-point `/ingest` → `/lint`), and suggest `/compact` after long `/teach` threads.
   - **High / Deep Reasoning tier** (`Claude Sonnet 5.5 (High)` or `Gemini 4 Neon (High)`; reserve `Claude Opus 5.5 (High)` / `Gemini 4 Neon (XHigh)` for large refactors) for `study-init` Phase 2–3 (clean-slate `/init`, JD/Benchmark Deep Search, Blueprint & Re-Benchmark), `weekly-study-plan`, and roadmap architecture.
